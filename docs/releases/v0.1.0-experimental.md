# Document Intelligence Workbench v0.1.0 — experimental portfolio release

A local invoice workbench that connects extraction suggestions to source-page evidence, preserves corrections as revisions, and exports JSON/CSV only after approval of the current revision. The release demonstrates an auditable AI workflow and measured extractor selection; it does not claim production financial correctness or arbitrary vendor accuracy.

This is prepared release text; the proposed tag is not published yet. Run the tag commands after publication.

## Try it

Python 3.12 is sufficient for the offline, four-case fictional invoice demo:

```sh
git clone --branch v0.1.0-experimental https://github.com/FlashPD/document-intelligence-workbench.git
cd document-intelligence-workbench
make demo-replay
```

Open the printed one-time session URL. Inspect source highlights, correct a suggestion or acknowledge a printed conflict, approve the revision, and download JSON/CSV. This mode replays saved OCR; it needs no Docker, model, paid API or downloads. Live uploaded documents use the separately prepared isolated Docker parser; pinned local-model assets require explicit setup.

## Measured results

| Evidence | Result | Scope |
|---|---|---|
| Default invoice rules | Header macro F1 0.9981; exact-row F1 0.9423 | All 180 synthetic test invoices, trusted previews/shared OCR |
| Optional local model | Header macro F1 0.9766; exact-row F1 0.7985 | Same 180 invoices; four failures scored; regression gate rejects promotion |
| CORD receipt diagnostic | Rules/model total F1 0.2435/0.1651; exact-row F1 0.0957/0.0204 | Separate 100-receipt test; five model failures; substantial domain gap |
| Human author review | 6/6 completed; active median 62.459 s; required headers exact 5/6; exact rows 19/20 | One author, fixed development cases, recorded OCR, five edits and one acknowledgment |

The author pilot retains two approved-record errors: `Illustration set 3}` instead of `Illustration set`, and `FO06-004` instead of `F06-004`. Original suggestions, timing events, revisions, approvals and exports are archived without rewriting those outcomes. Separate [corrected drafts](../post-pilot-corrections.md) fix those values in new revisions requiring fresh approval. There is no manual-entry baseline or time-saved claim. Human participation is reported by the author and is not authenticated by local hash checks.

## Engineering evidence

- Network-denied, resource-bounded parsing; sixteen recorded Docker workflow/recovery/resource checks, including timeout/OOM and checkpoint recovery.
- Immutable candidate revisions, stale-edit protection, current-revision approval and hash-verified exports.
- Durable leases/fencing, verified parser checkpoints and portable backup restoration.
- Complete paired invoice/receipt accounting, frozen settings, failure-inclusive scoring, uncertainty and representative errors.
- Source-linked review, keyboard controls, page-specific rotation and multi-page navigation.
- A completed evidence audit, eight-command clean-source verification, commit/tag checks, and offline restoration/rescoring of the author-pilot archive.

The captioned demo is a fifteen-second sequence assembled from browser screenshots, without audio. It illustrates the interface; its pacing is not measured extraction latency or human review time. Playback and source screenshots are inspected separately from the actual author study.

## Release boundaries

Single-user loopback prototype with audit labels rather than authenticated reviewer identities. Genuine scanner captures, semantic attribution sampling, controlled warm/cold/whole-application memory studies, deletion/retention, PC/GPU profiles, VLM experiments and a manual-versus-assisted user study remain deferred. Passing the portfolio checklist does not establish complete original-architecture acceptance, production certification, invoice authenticity, payment/tax suitability, or unattended approval safety.
