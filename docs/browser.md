# Browser review prototype

For an immediate demo needing only Python 3.12, run `make demo-replay`. The [offline replay guide](demo-replay.md) covers its four fictional cases, persistent session state, and recorded provenance. Live intake controls are unavailable in replay mode; the commands below run fresh processing.

Run `make dev` from the repository root with Python 3.12 and Tesseract English data installed. Open the one-time URL printed in the terminal. The server binds only to `127.0.0.1`. The URL sets an ephemeral, HTTP-only same-site session cookie, then redirects to a URL without the token. Every mutation also requires a same-origin request. Reviewer names are audit labels supplied by the user, not verified identities.

Choose **Clean sample** or **Conflicting total** to run fresh OCR on a committed, self-authored fixture. This does not use the Docker parser or a language model. Review-ready documents appear in descending [triage priority](review.md#review-queue-priority); the shown points and leading issue code help order work, but zero points do not establish correctness. Select any field to highlight the cited OCR line on the image. Correct a value to create a new revision; the original OCR text and source span remain in the record. For the conflicting-total example, enter a reason under `TOTAL_MISMATCH` to acknowledge the printed total, or correct the value. Approval applies only to the current revision. Export JSON or CSV, then use the verified download links.

The **Upload** control accepts one to twenty PDF, PNG or JPEG files under the same per-file limits as the CLI. Run `make parser-build` with Docker available first. Live processing runs automatically and serially; select **OCR rules** or the experimental **Local span model** before uploading. Individual batch failures remain visible. `make dev-model` verifies cached assets and supplies the pinned authenticated model server; its credentials remain server-side. Ordinary `make dev` offers rules processing. The [lifecycle runbook](lifecycle.md) explains cancellation, reprocessing, tracked deletion, restart behavior and storage limits. A failed job displays its error token and a retry action after cleanup is confirmed. PDF records can have up to ten pages; the page selector switches the raster, and selecting a cited field jumps to its source page. Review-only rotation keeps highlights aligned without changing stored coordinates. Uploaded previews are served only after a verified render; the two trusted sample fixtures use their allowlisted originals. The [historical real-model workflow](real-model-upload.md) retains its original two-fixture evidence.

This is a no-build local interface so the review workflow can be exercised on the current Mac. The architecture plan's FastAPI/React stack and authenticated identity are not implemented; the full held-out model comparison is pending. The deterministic suite exercises the HTTP handler in process. The [Chrome workflow check and scripted recording](browser-verification.md) now cover keyboard controls, cited highlights, four display rotations, multi-page navigation, corrections, approval, and downloaded export bytes on fictional development cases.

The [timed author-pilot mode](review-pilot.md) has a [refreshed Chrome verification](../evals/review-pilot-browser-2026-10-03-v5/report.json) on a disposable development fixture, covering page rendering/highlighting, pause/resume, approval, JSON export, and trial completion. Its automation is explicitly excluded from human review-time measurements. The pilot opens only its declared recorded candidates, keeps timing separate from extraction/review state, and labels replay provenance.

On field buttons, use ↑/↓ to move selection and keyboard focus, then Enter to focus the correction input. Other buttons and form controls retain native key events. Replayed records outside timed pilot mode are labeled **RECORDED OCR RULES · REPLAY**. Review-only rotation leaves the original image and stored evidence coordinates unchanged.
