# Spatial OCR row extraction

The experimental `ocr-rules-v0.4` extractor was **rejected for default promotion** after its calibration regression. The product and evaluation default remains `ocr_rules` v0.3. Use `eval-run-invoices --extractor spatial_rules` only to run the candidate explicitly. The candidate joins OCR fragments that occupy the same visual line. This addresses a development failure where a description, quantity, and prices arrive as different Tesseract line spans. It retains duplicate descriptions as separate rows, preserves missing cells, and links each captured value to the original spans that contain it.

The grouping uses disjoint horizontal boxes with at least half the smaller box's vertical extent overlapping. Every fragment must satisfy that relation with all other fragments in the group. It does not use the previous fixed 0.015 page-height search, which could borrow a nearby row's amount. Without geometry, a span remains independent. When explicit split `Description` and `Amount` headers establish a sideways reading direction, an extraction-only coordinate view joins columns on that page; the stored image and evidence boxes remain unchanged. Otherwise sideways line spans retain OCR order and are not spatially joined.

A description beside two explicit money columns can become a partial row with `quantity_not_observed`. Quantity is never inferred from price and total. Such a row raises blocking `INVALID_ROW_AMOUNT` for human review. Split header labels and values can also be recovered when the field was absent, allowing arithmetic validation to run when its observed components are available. Previously complete observed headers take precedence.

Captured values cite only intersecting OCR fragments. A description spanning two fragments cites both, and validation checks their joined source text while rejecting unrelated extra citations. Missing cells have no fabricated evidence. The extractor never creates synthetic span IDs or source boxes, corrects OCR characters from a vendor dictionary, or substitutes computed amounts for printed ones.

The recorded `invoice-preview-ocr-rules-v3` experiment bundles save the canonical OCR pages with each successful prediction and a source snapshot of extraction, OCR, contracts, validation, and the runner. The run identity binds that snapshot's hash, and resume rejects changed pipeline source. The offline verifier checks the snapshot, page contracts, source references, predictions, timings, and scored report. New v4 bundles also record the explicit extractor choice and reject changing it during resume. Historical v1/v2 bundles retain their existing verification path; they did not save OCR pages or extraction source. Pipeline snapshots document recorded implementation, rather than independently proving that code executed.

The method remains narrow: English, dot-decimal prices, explicit labels, and one-line rows or horizontal fragments. It does not recover text OCR never recognized, infer missing quantities, reliably join wrapped descriptions on separate visual lines, or parse arbitrary tax/locale conventions. Development examples guide implementation; repeated calibration measurements are diagnostics, and the held-out test families remain sealed.

The [development report](invoice-development-run.md#spatial-fragment-extraction--october-3-2026) records better row coverage alongside lower exact-row F1. The [calibration report](invoice-calibration-run.md#spatial-candidate-rejected--october-3-2026) records worse row detection and exactness and explains why the candidate stays experimental. Its grouping heuristics were not changed after viewing calibration results. Restoring the default and isolating the candidate changed dispatch and run metadata; replay over all 360 saved OCR inputs confirms both extractors still reproduce their respective recorded candidates.
